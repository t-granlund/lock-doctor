02 · The loop, with the gates visible

What actually happens when you talk

you say / record it→ Mockingbird transcribes→ Cedar plans in plain words→ your yes→ builds & tests→ your yes→ ships locally→ reports back

Gated, both directions

Nothing consequential runs without a human yes — and nothing leaves without one either. Commands, file changes, sends, deploys: each one shows its plan first and waits.

Secure by location

Your recordings, transcripts, and tools live on your machine, in your files. Customer PII stays out of prompts by default. API keys sit in local config — never pasted into a conversation.

Readable, always

Every change lands in files you own and git history you can read. Nothing is a black box; if you ever wonder what happened, the answer is a file you can open.

03 · The trust part, honestly

Uncertainty is a feature. Here’s how to use it.

The key to all of this is trusting the harness — and trust isn’t built by magic, it’s built by clarity. So the rule is simple: any uncertainty Cedar has, it states out loud, and asks. When it doesn’t know which fob, which price, which door — it stops and asks instead of guessing on your behalf. That’s not hesitation; that’s the harness respecting the fact that it’s your shop.

  • It shows its plan before it acts — you approve the how, not just the what.
  • It names what it doesn’t know — uncertainty is stated, never hidden in a confident guess.
  • It keeps receipts — every command, every edit, reviewable after the fact in plain files.
  • It fails safe — if a step can’t be done cleanly, it stops and tells you, rather than pushing something half-broken out the door.
“Once you see that the uncertainty is loud and the gates are real, the fear turns off — and the harness becomes the answer to building anything you want.”
04 · Your hands-on path

Four steps. One evening. Then you’re driving.

  1. Put the grove on your machine. A Mac or PC (Linux/WSL fine), Python 3.11+. Clone, sync, wake: 
    # the same commands that built everything in this package
git clone https://github.com/t-granlund/SPRUCE-GROVE-OS
cd SPRUCE-GROVE-OS
uv sync
uv run spruce-grove
    the grove on GitHub →   uv, if you need it →
  2. Pick a brain — one line of config. Tyler’s pick today is synthetic.new → — tuned his way. Any provider works the same: OpenAI, Anthropic, Gemini, Bedrock, your own endpoint. Swap any time; the brain is rented, the harness is owned. Everything sensitive stays in local config, never in a prompt.
  3. Say your first build out loud. Record it like Tyler did this morning — plain words, thinking out loud. Or type it. Try one of the six starters in the package: the listing audit, the parts brain, the after-hours intake. Cedar will plan it, show you, and wait for your yes at every gate.
  4. Run with it. Change your mind mid-build — say so. Want it different — say so. The tools are Apache-2.0-licensed, the source is yours, the mirrors are yours. There is no vendor to leave, because there was never a vendor in the middle.
